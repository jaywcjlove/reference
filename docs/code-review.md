代码审查备忘清单
===

五轴评审（正确性 · 安全性 · 可读性 · 性能 · 测试覆盖）速查，严重级别优先，评论格式固定，拒绝风格警察。

入门
---

### 审查前置检查

| 检查项 | 说明 |
|--------|------|
| Diff 行数 | **超过 400 行先拆 PR**，否则拒绝审查 |
| CI 是否绿 | CI 红灯时评论仅记录，不阻塞合并讨论 |
| PR 描述 | 必须说明"改了什么"和"为什么改" |
| 自审完成 | 作者应在提交前自行过一遍本清单 |

### 严重级别

| 级别 | 标记 | 含义 |
|------|------|------|
| 必须修复 | `Must fix` | 存在 bug、安全漏洞或数据风险，不修不合并 |
| 应该修复 | `Should fix` | 明显隐患或维护性问题，强烈建议修复 |
| 建议 | `Nit` | 可选改进，不阻塞合并，留作参考 |

### 评论格式

```
[轴] file:line 问题描述 -> 建议修复
```

示例：

```
[correctness] auth/login.go:42 nil 指针未检查，user 为空时必然 panic -> 在解引用前加 if user == nil { return ErrNotFound }
[security] api/upload.go:87 未校验文件扩展名，可上传 .php -> 白名单校验：allowedExt := map[string]bool{".jpg":true,".png":true}
[performance] db/query.go:115 循环内 N+1 查询 -> 改用 IN 子句批量拉取
```

五轴评审
---

### 正确性（Correctness）

| 检查点 | 常见问题 |
|--------|---------|
| 边界条件 | 空指针、空集合、零值、整数溢出 |
| 错误处理 | 错误被吞掉、错误码混用、panic 未恢复 |
| 并发安全 | 共享状态无锁、goroutine 泄漏、channel 死锁 |
| 业务逻辑 | 条件分支遗漏、状态机转换缺失 |
| 幂等性 | 重试场景下是否会重复写入或扣款 |

### 安全性（Security）

| 检查点 | 常见问题 |
|--------|---------|
| 输入校验 | SQL 注入、XSS、路径遍历、SSRF |
| 认证授权 | 接口缺少鉴权、越权访问、Token 未过期 |
| 敏感数据 | 密码/密钥硬编码、日志打印明文凭证 |
| 依赖安全 | 新增依赖是否有已知 CVE |
| 文件上传 | 未限制类型/大小，存储路径可预测 |

### 可读性（Readability）

> [!NOTE]
> 可读性评论只提"理解障碍"，不改风格（命名大小写、括号位置等由 linter 管）。

| 检查点 | 常见问题 |
|--------|---------|
| 命名语义 | 函数/变量名无法表达意图，需要注释才能读懂 |
| 注释准确性 | 注释与代码行为不符，或描述"是什么"而非"为什么" |
| 函数长度 | 单函数超过 60 行且逻辑混杂多个职责 |
| 魔法数字 | 裸露的数字/字符串常量，无名称无解释 |

### 性能（Performance）

| 检查点 | 常见问题 |
|--------|---------|
| N+1 查询 | 循环内触发数据库/RPC 调用 |
| 不必要分配 | 热路径内频繁 string 拼接、大对象拷贝 |
| 缓存缺失 | 高频只读数据每次重新计算或查询 |
| 索引缺失 | 新增查询字段未建索引（需 EXPLAIN 验证） |
| 超时控制 | 外部调用无超时/重试上限，可能级联阻塞 |

> [!TIP]
> 性能评论须附上"预估影响"，避免过早优化。无数据支撑时降级为 `Nit`。

### 测试覆盖（Test Coverage）

| 检查点 | 常见问题 |
|--------|---------|
| 新逻辑有无测试 | 新增核心路径缺对应单测 |
| 异常路径 | 只测 Happy Path，错误/边界分支无覆盖 |
| 测试隔离 | 测试依赖外部服务或共享全局状态 |
| 断言质量 | 只断言无报错，未验证返回值或副作用 |
| 测试数据 | 生产数据硬编码进测试，泄露隐私 |

评审流程
---

### 单次评审上限

```
最多提出 10 条评论（Must fix 优先）
超出部分记录到 PR 描述，留待下轮审查
```

### 评审优先级顺序

```
Must fix（correctness / security）
  ↓
Must fix（performance / test coverage）
  ↓
Should fix（任意轴）
  ↓
Nit（选填）
```

### 不在审查范围内

- 代码格式、缩进、括号风格（交给 linter）
- 变量命名大小写约定（交给 linter）
- 个人偏好性重构（无明确收益时不提）

复制即用清单
---

```markdown
## Code Review Checklist

### 前置
- [ ] Diff ≤ 400 行（超出请先拆分）
- [ ] CI 全绿
- [ ] PR 描述完整

### 正确性
- [ ] 空指针 / 空集合 / 零值边界已处理
- [ ] 错误未被静默吞掉
- [ ] 并发共享状态有锁保护
- [ ] 幂等性在重试场景下成立

### 安全性
- [ ] 所有外部输入已校验（SQL / XSS / 路径）
- [ ] 接口有鉴权，无越权风险
- [ ] 无硬编码密钥 / 密码
- [ ] 新增依赖无已知 CVE

### 可读性
- [ ] 函数命名能表达意图，无需注释才懂
- [ ] 注释描述"为什么"而非"是什么"
- [ ] 单函数 ≤ 60 行 / 职责单一
- [ ] 无裸露魔法数字

### 性能
- [ ] 无循环内 N+1 查询
- [ ] 热路径无不必要的大对象拷贝
- [ ] 外部调用有超时控制

### 测试覆盖
- [ ] 新增核心逻辑有对应单测
- [ ] 异常 / 边界路径有覆盖
- [ ] 测试不依赖外部服务 / 全局状态
- [ ] 断言验证了返回值或副作用

### 评论汇总（≤ 10 条）
| 级别 | 评论（[轴] file:line 问题 -> 建议） |
|------|--------------------------------------|
| Must fix | |
| Should fix | |
| Nit | |
```
